# Работа в репозитории хакатона

Основной репозиторий: https://github.com/BAITC-Hacks/hack-bdc1bfee-qonimai . Не создаём новый репозиторий и не используем прежнюю подготовительную папку mvp как основную.

## Что означает сохранение

- Ctrl+S сохраняет файл на компьютере ведущего.
- Commit сохраняет выбранные изменения в локальной истории Git.
- Push отправляет коммиты в репозиторий хакатона.
- Pull получает новые коммиты с GitHub. При работе втроём через Live Share этим управляет только ведущий.

## Подключение втроём

Ведущий открывает проект, запускает Live Share: Start Collaboration Session и отправляет ссылку двум участникам. Каждый гость устанавливает расширение Live Share от Microsoft в VS Code, входит в свой GitHub-аккаунт и вызывает Live Share: Join Collaboration Session. Ведущий подтверждает подключение и разрешает редактирование. Проверка — каждый меняет свою строку TEAM_CHECK.md и все сразу видят результат.

Гостям для Live Share не нужна отдельная копия проекта. При завершении сеанса ведущим совместное редактирование прекращается; сохранённые файлы остаются на его компьютере. Ссылка действует в пределах сеанса.

Право входить в Live Share и право отправлять изменения в GitHub — отдельные разрешения. Для самостоятельной работы каждый участник должен открыть репозиторий под своим аккаунтом и получить доступ от организации хакатона. Если репозиторий не виден или нет разрешения на запись, передайте GitHub-логин организаторам или администратору репозитория. Не создавайте публичную копию приватного репозитория.

## Распределение файлов

Будущие модули ещё не созданы; перечислены границы ответственности.

Обновление после приёмки парсера: contracts.py и analysis/model_output.py уже реализованы. Экспорт временно передан агенту B по prompts/AGENT_B_DOCX.md: участник 3 пока работает только над UI и не меняет export_docx.py или тесты экспорта параллельно. Актуальные назначения всегда сверяйте с PROJECT_STATE.md.

| Участник | Файлы | Результат |
|---|---|---|
| 1 — аудио | audio/, tests/audio/, docs/audio.md | Подготовка аудио, локальное распознавание, сегменты с говорящими и таймкодами |
| 2 — анализ | analysis/, tests/analysis/, docs/analysis.md | Саммари, поручения, сроки, ответственные, проверка JSON |
| 3 — интерфейс и сборка | app.py, export_docx.py, tests/export/, docs/ui.md | Интерфейс, исправление результатов, DOCX, сборка README |
| Координатор | contracts.py, общие fixtures/, зависимости, PROJECT_STATE.md | Согласование форматов и изменений общих файлов |

В одном файле согласуйте разные участки. Пока участник редактирует файл, другой не запускает ИИ-команду полной замены того же файла. Код из разных рабочих чатов не объединяется автоматически.

## Первый рабочий сеанс

1. Проверить Live Share через TEAM_CHECK.md.
2. Участник 1 собирает характеристики машин; участник 2 готовит вымышленные диалоги с ожидаемыми результатами; участник 3 проверяет среду и описывает путь пользователя.
3. В общем чате согласовать формат данных до независимого написания модулей.
4. Выполнять одну небольшую задачу за раз: точный файл → изменение → команда проверки → фактический результат.
5. После проверки ведущий открывает Source Control, просматривает изменения, выбирает нужные файлы кнопкой +, пишет краткое сообщение и нажимает Commit, затем меню ... → Push.
6. Открыть репозиторий в браузере и проверить последний коммит. Не использовать Force Push.

Git-автор и email настроены только для локальной копии ведущего по его GitHub-аккаунту; общие настройки компьютера не меняются. GitHub-авторизация у каждого своя. Пароли и токены в файлы и чаты не передавать.

## Отчёт в общий чат

```text
Участник:
Что сделано:
Файлы:
Команда проверки и рабочая папка:
Ожидаемый результат:
Фактический результат:
Проблемы:
Предложения по общим форматам и зависимостям:
```

Ошибки присылайте полным текстом после удаления секретов и чувствительных данных. Реальные записи и транскрипты сюда не отправляйте. Заглушки отмечайте явно.

## Ограничения проекта

Обработка речи и текста только локально или в закрытом контуре. Используем вымышленные тестовые данные. Уведомляем участников о записи и обработке ИИ. Имя говорящего подтверждается человеком; автор реплики не обязательно исполнитель поручения. Неизвестные имена и сроки не придумываем. Реальные аудио и транскрипты держим вне общей папки.
