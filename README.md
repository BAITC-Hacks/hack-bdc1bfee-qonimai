# QonimAI — протоколы совещаний с проверкой поручений

QonimAI предназначен для локального преобразования совещаний на русском,
казахском и смешанном языке в протокол с поручениями. Цель продукта —
помочь участникам проверить исполнителей, сроки и основания каждого поручения
перед сохранением документа.

**Состояние на 23 сентября 2026: частичный технический прототип, не полный MVP.**
Работают контракт данных, валидатор, проверка JSON будущей модели и экспорт
проверенного снимка в DOCX. Распознавание аудио, диаризация, локальный анализатор
и веб-интерфейс ещё не реализованы. Демонстрация использует заранее написанные
синтетические данные; она не подтверждает качество моделей.

## Что уже работает

| Возможность | Реализация и границы |
|---|---|
| Проверка транскрипта | Сегменты, таймкоды, ссылки на спикеров, подтверждение имён |
| Проверка поручений | Автор отдельно от исполнителя, неизвестные значения, причины уточнения, исходные сроки и даты |
| Проверка ответа модели | Строгий JSON; отклонение повреждённого ответа и попыток выдать модельный результат за ручные правки |
| Контроль версии | Запрет экспорта устаревшего или не просмотренного снимка |
| Экспорт DOCX | Саммари, решения, поручения, источники, полный транскрипт, исходные и изменённые человеком значения |
| Демонстрация | CLI на синтетических случаях, явная отметка «модели не запускались» |

Валидатор проверяет формальные правила и некоторые правила сроков. Наличие
ссылки на реплику само по себе не доказывает истинность утверждения.
Парсер **не вызывает модель** и **не извлекает поручения**.
Подтверждение просмотра обязан получать вызывающий интерфейс; автоматическая
передача номера версии не заменяет человека.

## Быстрый запуск на Windows / PowerShell

Нужны Git, доступ к приватному репозиторию и рабочий CPython 3.12.
Проверенная версия — 3.12.14, другие версии для всей сборки не подтверждены.
В новом терминале, из папки для проектов:

```powershell
git clone https://github.com/BAITC-Hacks/hack-bdc1bfee-qonimai.git
Set-Location hack-bdc1bfee-qonimai
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-export.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Если репозиторий уже открыт, клонировать его повторно не надо: начните
с проверки Python в корне проекта. Вход в GitHub — через штатное окно Git,
токены в команды, файлы и чаты не вставляем. Если `python` открывает Microsoft
Store, укажите путь к уже установленному интерпретатору; команды не были
рассчитаны на заглушку WindowsApps.

После просмотра входа и ожидаемого результата случая `USER_CLARIFIED_DUE`
в [fixtures/synthetic_cases.json](fixtures/synthetic_cases.json):

```powershell
New-Item -ItemType Directory -Force exports | Out-Null
.\.venv\Scripts\python.exe -m examples.export_fixture --case USER_CLARIFIED_DUE --output exports/demo_synthetic_user.docx --confirm-reviewed
.\.venv\Scripts\python.exe -m examples.export_fixture --case STRESS --output exports/demo_synthetic_stress.docx --confirm-reviewed
```

Ожидается сообщение об успешном сохранении синтетического DOCX. Откройте
файлы в локальном редакторе документов и просмотрите все страницы.
`--confirm-reviewed` означает, что демонстратор просмотрел именно этот
синтетический снимок. Без флага CLI откажется экспортировать. Существующий
файл по указанному пути может быть заменён успешным экспортом.

Запуска Streamlit или команды загрузки аудио в этой версии **нет**.
Для воспроизведения экспорта не нужны GPU, CUDA, API-ключ или веса модели.

## Архитектура и файлы

Реализованный путь:

```text
Синтетический Transcript + ожидаемый AnalysisResult
    → contracts.validate_snapshot / validate_export
    → export_docx.export_docx
    → локальный DOCX

Строка JSON будущей локальной модели
    → analysis.model_output.parse_model_output
    → проверенный AnalysisResult либо явная ошибка
```

Планируемая полная цепочка: аудио → локальные ASR и диаризация → подтверждение
имён → локальное извлечение поручений и саммари → редактирование пользователем
→ проверка актуальной версии → DOCX. До экспорта эта цепочка пока не собрана.

- `contracts.py` — контрактные проверки.
- `analysis/model_output.py` — строгий парсер, без модели.
- `export_docx.py` — атомарное локальное сохранение DOCX.
- `examples/export_fixture.py` — воспроизводимая демонстрация.
- `fixtures/synthetic_cases.json` — 16 вымышленных входов и ожидаемых результатов.
- `tests/` — автоматические проверки реализованных модулей.
- `requirements-validation.txt`, `requirements-export.txt` — фиксированные зависимости.
- `docs/CONTRACT_V1.md` — действующий формат, правила сроков и ручных правок.
- `docs/submission/` — пакет для жюри, приёмка и ограничения.
- `PROJECT_STATE.md` — краткая передача контекста.

API и примеры: [контракт v1](docs/CONTRACT_V1.md),
[анализ/парсер](docs/analysis.md), [экспорт](docs/export.md).

## Среда и зависимости

Проверенная машина: Windows 11 Pro x64, Intel Core i7-13620H, 15,7 ГБ RAM,
Intel UHD Graphics; дискретная NVIDIA не обнаружена. Это описание среды
тестирования, **не измеренный минимум ресурсов** и не рекомендация оборудования
для ещё не выбранных моделей.

Для текущих модулей зафиксированы CPython 3.12.14 (среда проверки),
tzdata 2026.3 / IANA 2026c, python-docx 1.2.0, lxml 6.1.1,
typing_extensions 4.16.0. Пакеты перечислены в requirements.
IANA нужна для календарных правил; отсутствие базы выдаётся как ошибка среды.
Показатели тестов и длительности — в
[отчёте повторной проверки](docs/submission/VERIFICATION_REPORT.md).

## Подготовка и запуск без загрузки зависимостей

Первое получение Python и пакетов требует доступного дистрибутива или интернета.
На машине с теми же ОС, архитектурой и версией Python заранее подготовьте колёса:

```powershell
python -m pip download --only-binary=:all: -r requirements-export.txt --dest wheels
python -m venv .venv-offline
.\.venv-offline\Scripts\python.exe -m pip install --no-index --find-links wheels -r requirements-export.txt
.\.venv-offline\Scripts\python.exe -m unittest discover -s tests -v
```

Сам экспорт и тестовые данные локальные. Проверка установки из локальных
колёс выполнена; дополнительный запуск тестов с запретом Python socket описан
в отчёте. Это не доказательство изоляции всей ОС: физическое отключение сети
и полная модельная цепочка пока не проверены.

**Модели не выбраны, не скачаны и не включены в репозиторий.** Поэтому сейчас
нет инструкций получения конкретных весов и подтверждённых лицензий моделей.
Перед добавлением моделей нужно проверить их доступность, лицензии, размер,
память и короткий пример; подготовить веса заранее и указать локальные пути.
Обработка реальных данных через внешние API запрещена.

## Данные и ограничения

Все fixtures вымышлены. Аудио, реальные транскрипты, секреты и веса в Git
не добавляем; `.gitignore` — дополнительная защита, не гарантия отсутствия утечки.
Реальные записи не передаём в ИИ-чаты. Участников заранее уведомляем о записи
и обработке ИИ; пример уведомления и границы защиты:
[данные и ограничения](docs/submission/DATA_AND_LIMITATIONS.md).

Казахские примеры ожидают проверки человеком; качество RU/KK/смешанного ASR,
диаризации и извлечения поручений не измерялось. PDF-экспорта нет.
DOCX автоматически проверен на текст и структуру; визуальная приёмка всех
страниц не завершена из-за отсутствия доступного рендерера.

Прямые подключения к Teams/Zoom/Meet, live-поток и напоминания не реализованы.
Обязательность этих функций уточняется у организаторов. Загрузка готовой записи
остаётся предварительным решением для следующего этапа и тоже пока не реализована.
Исходный Google Docs недоступен для чтения; чек-лист составлен по требованиям,
предоставленным командой, и не выдаётся за полный официальный регламент.
