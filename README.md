# hack-bdc1bfee-qonimai
Hackathon team repository for QonimAI

## Совместная работа команды

Это единственный основной репозиторий проекта: https://github.com/BAITC-Hacks/hack-bdc1bfee-qonimai . Вся разработка, документация и история изменений ведутся здесь. Новый репозиторий создавать и команду Publish to GitHub выполнять не нужно.

Для одновременного редактирования используем VS Code Live Share. GitHub хранит версии кода; Live Share передаёт изменения между открытыми редакторами.

1. Ведущий открывает локальную копию этого репозитория в VS Code.
2. Через Ctrl+Shift+P выбирает Live Share: Start Collaboration Session, входит через GitHub при запросе и передаёт ссылку двум участникам.
3. Каждый участник устанавливает расширение Live Share от Microsoft, входит в свой аккаунт и выбирает Live Share: Join Collaboration Session. На macOS палитра команд открывается Cmd+Shift+P.
4. Ведущий подтверждает подключения. Все открывают TEAM_CHECK.md и меняют свою строку. Проверка успешна, когда каждый видит изменения остальных сразу.
5. Только ведущий сохраняет версии через Commit и отправляет их через Push. Пока идёт общий сеанс, ветку не переключаем. Для дальнейшей независимой работы будем использовать отдельные ветки и pull requests.

Подробности, роли и порядок проверок: [TEAM_GUIDE.md](TEAM_GUIDE.md). Текущее состояние: [PROJECT_STATE.md](PROJECT_STATE.md).

Для второго ИИ-агента подготовлены [полная передача контекста](docs/AGENT_HANDOFF.md) и [стартовый промпт](prompts/AGENT_B_START.md). Первая задача агента — проект контрактов и контрольных примеров; работающие модели пока не выбраны.

Первая задача агента B проверена. Действуют [контракт v1](docs/CONTRACT_V1.md) и [16 синтетических примеров](fixtures/synthetic_cases.json). [Решения координатора](docs/REVIEW_AGENT_B_01.md) и [следующая задача агента B](prompts/AGENT_B_NEXT.md) описывают переход к реализации валидатора. Казахские примеры ещё требуют проверки человеком; модели и приложение не проверены.

## Статус MVP

Подготовлена среда совместной разработки и реализован contracts.py: проверка транскрипта, результата анализа, ссылок, сроков, ручных правок и условий экспорта. Также работает analysis.model_output.parse_model_output: строгая проверка сырого JSON-ответа будущей локальной модели. Модель эта функция не вызывает. Распознавание речи, диаризация, модель анализа, интерфейс и генератор DOCX пока не реализованы. Python и модели всей цепочки будут выбраны после проверки оборудования команды. Приложение ещё нельзя запустить.

## Проверка валидатора

Координатор проверил CPython 3.12.14 с tzdata 2026.3: 92 теста, 91 успешно выполнен, один пропущен (для среды без базы зон). Все 16 канонических случаев прошли. Проверка без базы — 72 выполнены, 20 пропущены; это не полноценная рабочая конфигурация календарных сценариев. Подробности — [приёмка валидатора](docs/REVIEW_AGENT_B_02.md).

На машине с установленным рабочим Python, из корня репозитория:

```text
python -m pip install -r requirements-validation.txt
python -m unittest discover -s tests -p test_contracts.py -v
```

Установка tzdata — подготовка среды и может требовать интернет; сами тесты используют локальные вымышленные данные. На Windows Python zoneinfo может не найти системную базу IANA, поэтому зависимость явно указана — [документация Python](https://docs.python.org/3/library/zoneinfo.html#data-sources). Это зависимости только валидатора, не финальный стек моделей. Если используется virtualenv, выполняйте команды его интерпретатором. Чистое окружение приложения и сквозной offline-запуск ещё не проверены.

В уже доступной среде ведущего PowerShell можно выполнить без установки:

```powershell
& 'C:\Users\Admin\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -m unittest discover -s tests -p test_contracts.py -v
```

Этот путь специфичен для компьютера ведущего; другим участникам нужен их собственный Python.

## Обработка данных

В GitHub и Live Share передаём код, документацию и вымышленные текстовые примеры. Аудио, транскрипты, модели, секреты и результаты обработки храним отдельно от общей папки. Реальные данные совещаний не открываем в совместном сеансе, общем терминале или отладчике и не отправляем в облачные API/ИИ-чаты. Все модели обработки должны работать локально либо на сервере в закрытом контуре.

Добавлены исключения Git и Live Share. Отключена автоматическая передача терминалов, портов и файлов вне проекта. Исключения не распознают чувствительный текст, вставленный в обычный исходный файл: перед коммитом проверяем содержимое.

Live Share использует внешнюю инфраструктуру для входа и установления соединения. Его используем только для совместного написания кода на вымышленных примерах. Перед записью участники должны быть уведомлены о записи и обработке с помощью ИИ.
