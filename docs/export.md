# Экспорт проверенного снимка в DOCX

Реализован участок «проверенный снимок → validate_export → настоящий DOCX». Это не распознавание речи и не вызов модели. Экспорт принимает формат docs/CONTRACT_V1.md и не меняет входные объекты.

## Среда

Координатор зафиксировал зависимости в requirements-export.txt. В выбранном рабочем Python установку выполняют из корня репозитория:

```text
python -m pip install -r requirements-export.txt
```

Предпочтительно отдельное окружение, не используемое другой задачей. В текущей проверке установки не потребовалось: уже доступны Python 3.12.14, python-docx 1.2.0, lxml 6.1.1, typing_extensions 4.16.0 и tzdata 2026.3 (IANA 2026c). Это среда экспорта/валидации, не выбор стека моделей. При отсутствии IANA экспорт возвращает ошибку среды; фиксированное смещение или UTC не подставляются.

## Вызов из приложения

```python
from export_docx import export_docx

# transcript и analysis — актуальный согласованный снимок.
# reviewed_revision задаёт интерфейс после реального просмотра пользователем.
# Каталог назначения уже должен существовать.
result = export_docx(transcript, analysis, reviewed_revision, target_path)
```

При успехе возвращается `{status: "ok", data: {path, source_revision}, error: null}`. path — абсолютный локальный путь созданного файла; source_revision — версия экспортированного анализа. Функция не устанавливает просмотр и не обновляет source_revision автоматически.

Первым выполняется неизменённый `contracts.validate_export`. При нескольких ошибках фиксированный приоритет: TIMEZONE_DATA_UNAVAILABLE → INVALID_INPUT → INVALID_MODEL_OUTPUT → STALE_ANALYSIS → NO_CONTENT → REVIEW_REQUIRED. Неизвестный валидаторный код обрабатывается как INVALID_MODEL_OUTPUT. Сначала исправляют первичную причину и повторяют проверку. Неудачный вход не создаёт файл, не заменяет существующий и не начинает файловые операции.

Все ошибки имеют оболочку `{status: "error", data: null, error: {code, message, retryable: false}}`. Сообщения фиксированы, без исходного текста, исключений или чувствительного пути. Ошибка структуры или среды отличается от ошибки записи EXPORT_FAILED. Прерывания KeyboardInterrupt/SystemExit распространяются; собственный временный файл при этом очищается по возможности.

## Путь и сохранение

Принимаются str или PathLike с локальным именем `.docx` (регистр расширения не важен). Родительский каталог должен существовать; экспортёр не создаёт его скрыто. Относительный путь определяется относительно рабочей папки вызова. URL, UNC, ссылки на каталоги, символические ссылки, Windows junction, зарезервированные имена устройств, альтернативные NTFS-потоки и Windows-сетевые диски отклоняются. Сеть и внешние сервисы функция не вызывает. Проверки путей тестировались на Windows; особенности других ОС и сетевых файловых систем требуют отдельной проверки.

После проверки снимка и пути создаётся собственный временный `.docx` в том же каталоге. Полностью сохранённый файл повторно открывается python-docx для проверки контейнера и лишь затем заменяет назначение через `os.replace`. Существующий файл может быть заменён успешным вызовом: вызывающая сторона должна выбрать нужное назначение. При ошибке сохранения/замены старый файл остаётся неизменным. Не удаляются чужие временные файлы или целевой файл. Если собственный временный файл заблокирован ОС, очистка может не выполниться; целевой файл ради очистки не затрагивается.

## Что находится в документе

- Заголовок «Протокол совещания», дата и часовой пояс именно из meeting, либо явное неизвестное значение.
- Подтверждённые участники. Неподтверждённый голос отображается как спикер; подсказка имени прямо отмечена неподтверждённой.
- Саммари и решения с источниками. При отсутствии решений/поручений есть явная надпись об их отсутствии.
- Последовательные блоки поручений: описание, исполнитель, автор, исходный срок, нормализованная дата, причины уточнения и ссылки. Автор не назначается исполнителем по умолчанию. Неизвестное не превращается в строку null.
- Для каждого пользовательского изменения task/summary/decision — «Уточнено пользователем», исходные и актуальные значения изменённых полей и reason. Исходный отсутствовавший срок остаётся виден и после задания даты пользователем.
- Полный текущий транскрипт в приложении: исходный порядок, id для ссылок, таймкоды в секундах, говорящий и текст. Казахские символы, табуляция, пунктуация и логические переносы сохраняются. CRLF/CR отображаются как один логический перенос LF, как принято в Word; недопустимые XML-символы не удаляются молча, а приводят к EXPORT_FAILED.

Оформление: Letter portrait, основной Arial 11 pt, встроенные стили чёрных заголовков, без декоративных блоков. Детали поручений оформлены абзацами, а не широкой таблицей с мелким текстом. Транскрипт начинается с новой страницы; длинные абзацы могут продолжаться на следующей. Номер страницы добавлен в нижний колонтитул для навигации. Это структурные настройки; визуальная корректность конкретного документа должна проверяться рендером.

## Только синтетическая демонстрация

Пример читает канонические вымышленные fixtures. STRESS создаётся отдельно в коде и не меняет общий набор. Никаких реальных записей или модельных ответов этот CLI не загружает.

Сначала просмотрите выбранный fixture или `build_stress_case()` в examples/export_fixture.py. В PowerShell из корня репозитория создайте выбранную папку и выполните:

```powershell
New-Item -ItemType Directory -Path exports -Force
python -m examples.export_fixture --case USER_CLARIFIED_DUE --output exports/demo_synthetic_user_clarified_due.docx --confirm-reviewed
python -m examples.export_fixture --case STRESS --output exports/stress_synthetic.docx --confirm-reviewed
```

Без --confirm-reviewed файл не создаётся: флаг означает просмотр именно выбранных вымышленных данных, а не автоматическое одобрение будущей модели. Имя файла должно содержать `synthetic`. В консоли и самом DOCX добавляется «Синтетический пример — модели не запускались». CLI не подменяет canonical snapshot ради этой надписи: маркирует только свою копию документа во временном файле и затем атомарно заменяет целевой файл.

STRESS содержит несколько поручений с неизвестными значениями, пользовательские правки всех трёх типов, длинные реплики, непрерывную строку и символы Ә Ғ Қ Ң Ө Ұ Ү Һ І ә ғ қ ң ө ұ ү һ і. Проверка этих букв подтверждает сохранение текста, но не правильность казахского языка.

## Тесты и визуальная проверка

```text
python -m unittest discover -s tests -p test_export_docx.py -v
python -m unittest discover -s tests -p test_*.py
```

Тесты создают файлы только в TemporaryDirectory и читают содержимое python-docx/XML, проверяют ошибки, атомарную замену, сохранность исходных файлов и отсутствие мутаций/утечек. Они не заменяют рендер: не обнаруживают, например, визуальную обрезку или замену шрифта.

**Текущий блокер визуального контроля:** bundled-среда 26.909.12148 на Windows не содержит LibreOffice. Загрузчик зависимостей не вернул его путь; поиск внутри bundle не нашёл soffice. Штатный render_docx.py на Windows использует установленный desktop LibreOffice, что запрещено заданием. Проверка resolver с PATH только из bundled-каталогов дала `FileNotFoundError: LibreOffice soffice.exe was not found on PATH`. Desktop LibreOffice не использовался, офисные пакеты не устанавливались. Poppler доступен, но не преобразует DOCX в PDF.

Поэтому созданные контрольные DOCX **не проверены визуально**, просмотрено 0 страниц. Для закрытия критерия координатору нужна среда с разрешённым bundled LibreOffice: выполнить render_docx.py для обоих файлов, открыть ВСЕ PNG-страницы, проверить переносы, длинную строку, шрифты, ручные исправления и границы страниц. При дефектах исправить оформление и повторить рендер. До этого образцы нельзя объявлять визуально готовыми для демонстрации.

Фактические результаты тестов, имена контрольных файлов и SHA передачи — в docs/agent-b/DOCX_REPORT.md. Модели, распознавание, интерфейс и вся цепочка без интернета остаются вне выполненной проверки.
