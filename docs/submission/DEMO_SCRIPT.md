# QonimAI: честная демонстрация текущего прототипа за 3–5 минут

**Статус:** сценарий для имеющегося участка «вымышленный снимок → проверка → DOCX». Он не демонстрирует распознавание, диаризацию, работу LLM или Streamlit: этих модулей пока нет. Экспорт реализован; координатор независимо повторил 56 тестов экспорта успешно. Команды выполнять в версии, содержащей `export_docx.py` и `examples/export_fixture.py`. Визуальная приёмка документов на момент подготовки сценария ещё открыта.

## Подготовка перед выступлением

1. Открыть корень локальной копии репозитория хакатона и записать фактический коммит командой `git rev-parse HEAD`.
2. Убедиться, что есть `examples/export_fixture.py` и `export_docx.py`, а зависимости [requirements-export.txt](../../requirements-export.txt) установлены в отдельном рабочем окружении. Установка выполняется заранее, не во время выступления.
3. Прочитать выбранные случаи в [fixtures/synthetic_cases.json](../../fixtures/synthetic_cases.json): `RU_EXPLICIT`, `NO_DUE`, `USER_CLARIFIED_DUE`. Их `expected` — вручную подготовленный эталон, а не выход модели.
4. Выполнить регрессию `python -m unittest discover -s tests -p 'test_*.py'`. Сохранить фактический результат; число тестов не заменяет демонстрацию функций.
5. Сформировать документы и визуально проверить все страницы в локальном Word/разрешённом офисном просмотрщике. Если доступен принятый renderer, сохранить отрисованные страницы и проверить их. Показать вымышленные имена, исходный срок, ручную правку, источники и приложение с транскриптом.
6. Подготовить отдельный каталог с копией заранее созданного синтетического DOCX. На резервном файле сохранить маркировку «Синтетический пример — модели не запускались»; в речи назвать его ранее выполненным запуском.
7. Закрыть окна с реальными данными, токенами и личной перепиской. Данные выступления должны быть целиком вымышленными.

Команды ниже для PowerShell, из корня репозитория, с уже выбранным рабочим Python. Если используется виртуальное окружение, вместо `python` укажите его интерпретатор. Папку создаёт ведущий; `--confirm-reviewed` передаётся только после чтения именно выбранного вымышленного случая.

```powershell
New-Item -ItemType Directory -Path exports -Force
python -m examples.export_fixture --case RU_EXPLICIT --output exports/demo_synthetic_ru_explicit.docx --confirm-reviewed
python -m examples.export_fixture --case USER_CLARIFIED_DUE --output exports/demo_synthetic_user_clarified_due.docx --confirm-reviewed
```

Ожидается успешный выход CLI и два настоящих DOCX с явной синтетической маркировкой. Если команда сообщает ошибку, файл не выдавать за готовый. Для проверки оформления казахских букв отдельно используйте STRESS согласно [документации экспорта](../export.md); этот набор также не доказывает языковое качество распознавания.

Для трёх минут сократить показ кода и оставить один DOCX. Не ускорять презентацию за счёт скрытия ограничений.

## Резерв при сбое

Произнести: «Живой экспорт сейчас не завершился. Показываю ранее созданный на вымышленных данных документ; модели при его создании не запускались». Открыть локальный резервный DOCX, показать ту же маркировку и содержимое. Не называть резерв результатом текущего запуска.

Уже подготовлен [сохранённый текст ранее выполненного синтетического экспорта](evidence/DEMO_PREVIOUS_RUN.md). Если показать DOCX невозможно, откройте этот файл и прямо скажите: «Это текст ранее созданного документа; оформление страниц сейчас не демонстрируется». Источник и ожидаемый анализ вымышлены, модели не запускались. Это запасной показ содержимого, не замена приёмке DOCX.

Резервная видеозапись пока не подготовлена. При её создании записать реальный повторяемый запуск, оставить видимую маркировку синтетических данных, указать проверенный коммит. Реальную запись совещания и личную переписку в видео не включать.

## Что менять после появления полной цепочки

Сценарий «проблема → запись → результат → проверка поручений → экспорт → ценность» становится допустимым после успешной обработки настоящего тестового аудио локальными моделями. Тогда заменить показ готового JSON загрузкой вымышленной записи и показать фактическое время обработки на указанном оборудовании. Заранее проверить RU/KK/MIXED, разделение голосов, неизвестные поля, ручную проверку и DOCX. До этого фразы «распознали запись», «модель выделила поручения», «работает на трёх языках» использовать нельзя.
