Функция сначала проверяет transcript и при его ошибке не разбирает ответ. JSON принимается целиком, без Markdown, окружающего текста и исправлений. Дубликаты ключей, NaN/Infinity, переполнение float, ошибки синтаксиса и недоступная глубина возвращают INVALID_MODEL_JSON. Корректный JSON неверной схемы, состояния, версии или ссылок — INVALID_MODEL_OUTPUT.

Ответ модели с error или непустым user_edits никогда не становится доверенным сообщением/ручной правкой. Для пустого транскрипта допустим только согласованный no_speech, для непустого — ok. Успешный объект возвращается после validate_snapshot без изменения дат, ключей, source_revision и без reviewed_revision. Все созданные функцией ошибки имеют фиксированные сообщения и retryable=false.

## Ограничения, решения и вопросы

1. **Граница доверия.** Валидный пользовательский USER_CLARIFIED_DUE проходит validate_snapshot, но обязан быть отклонён как raw output модели. Модельные ошибки запуска тоже отклоняются: MODEL_UNAVAILABLE/RESOURCE_EXHAUSTED формирует будущий адаптер выполнения. Именно он решает, повторять ли вызов модели; parser повторов не делает.
2. **Приоритет входа.** Если transcript одновременно невалиден и база IANA недоступна, возвращается TIMEZONE_DATA_UNAVAILABLE; разбор строки не начинается. После восстановления среды проверка выявит оставшиеся ошибки входа. Отсутствие базы не выдаётся за неверную дату модели и не заменяется UTC.
3. **Числа и глубина.** Запись вроде 1e999 имеет числовой синтаксис JSON, но не представляется конечным float Python, поэтому отклоняется как INVALID_MODEL_JSON. Ограничения декодера на глубину и число цифр целого не ослабляются; числовые значения не чинятся. Никакие глобальные настройки Python не меняются.
4. **Ошибки процесса.** Перехватываются только ожидаемые ошибки разбора ValueError/RecursionError/OverflowError в вызове JSON-декодера. KeyboardInterrupt, SystemExit и неожиданные ошибки приложения не маскируются. Лимиты памяти, длины ответа, времени и выполнения будущей модели остаются задачей адаптера; произвольный ответ не ограничен здесь новым несогласованным порогом.
5. **Смысл результата.** Parser не проверяет истинность произвольных фактов, не извлекает поручения и не переводит текст. Сохраняются ограничения детерминированного валидатора. no_speech лишь согласован с пустыми segments; различение тишины и сбоя ASR остаётся аудиомодулю.
6. **Просмотр и правки.** UI создаёт user_edits после действия пользователя, сохраняет original, управляет версиями и просмотром. Успешный parser сам не подтверждает результат и не разрешает экспорт.

Дополнительные зависимости не предлагаются: для этой части достаточно стандартной библиотеки, существующего contracts.py и уже утверждённой базы зон. Следующее решение координатора — назначить владельца адаптера выполнения выбранной локальной модели и согласовать его ресурсные лимиты после проверки оборудования.

Не проверены: любая модель, качество анализа/ASR/диаризации, смысловая корректность казахского человеком, реальный UI/DOCX, полная цепочка без внешнего интернета, производительность модели. Новое чистое окружение в этой задаче не создавалось; проверка координатора описана в REVIEW_AGENT_B_02.md и не приписывается агенту B.
