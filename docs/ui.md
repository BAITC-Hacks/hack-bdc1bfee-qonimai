# Локальный интерфейс QonimAI

Запуск из корня репозитория после установки согласованных зависимостей:

```powershell
python -m streamlit run app.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

Интерфейс содержит два раздельных режима. «Аудиозапись» вызывает реальные локальные модули `audio.pipeline.transcribe` и `analysis.local_model.analyze`. «Синтетические примеры» читает заранее подготовленные входы и ожидаемые результаты из fixtures; он явно помечен, модели не вызывает, а его DOCX содержит такую же маркировку. При переключении режима снимок и подтверждение очищаются. Наличие кнопок не доказывает успешный запуск моделей: требуется проверка с подготовленными весами.

## Порядок работы

1. Прочитать уведомление и подтвердить, что участники уведомлены и обработка разрешена. Реальные данные не открывать через Live Share и не отправлять в облачные API/чаты.
2. В аудиорежиме выбрать WAV/MP3/M4A/OGG до 50 МБ и 5 минут, указать подтверждённые имена участников. Если дата неизвестна, оставить соответствующий флаг выключенным: системное время не заменяет время встречи.
3. Указать пути уже подготовленных локальных весов и локальный сервер анализатора. Значения по умолчанию берутся из `QONIMAI_ASR_MODEL`, `QONIMAI_SPEAKER_MODEL`, `QONIMAI_ANALYSIS_URL`; сами поля позволяют их уточнить. При наличии файлов в проекте используются `models/whisper-small` и `models/speaker/wespeaker_en_voxceleb_resnet34_LM.onnx`. По умолчанию анализатор ожидается на `http://127.0.0.1:8081`.
4. Запустить распознавание. Временный локальный файл аудио удаляется при выходе из блока обработки, включая ошибки. Ограничение длительности проверяет аудиомодуль; UI дополнительно ограничивает размер файла.
5. Прослушать запись, подтвердить соответствие голосов людям, исправить текст при необходимости, сохранить изменения. Автор реплики и исполнитель поручения — разные поля. Неподтверждённый голос не получает имя автоматически.
6. Запустить локальный анализ. Повторный запуск показывает текущий и новый варианты для сравнения; новый результат заменяет старый только после отдельного подтверждения. Можно оставить прежний. Если запуск неудачен, прежний результат не заменяется, подтверждение просмотра сбрасывается.
7. Просмотреть поручения, саммари, решения и источники. При исправлении укажите объяснение; исходные значения сохраняются в `user_edits`. Ссылки, автор и исходная формулировка срока не подменяются этим редактором.
8. После исправления отдельно сверить содержание с репликами и подтвердить актуальность. Затем отдельно отметить просмотр перед экспортом. Любая сохранённая правка сбрасывает это подтверждение; устаревший снимок не экспортируется.
9. Подготовить и скачать настоящий DOCX. Документ создаётся во временном каталоге, читается в память, каталог удаляется. Скачанный пользователем файл хранится на его устройстве.

В аудиорежиме также есть кнопка «Испытать на синтетической аудиозаписи»: она читает настоящий локальный WAV `fixtures/audio/synthetic_ru_two_speakers.wav` и вызывает модели. Из сопровождающего JSON используются только известные метаданные совещания и список участников; эталонные реплики/поручения не подставляются. Такая запись получает отдельную маркировку, отличную от текстовых fixtures без вызова моделей. Успешность этой цепочки и качество результата координатор проверяет отдельно.

Данные результатов хранятся в памяти Streamlit-сеанса, без записи транскриптов в логи. Кнопка «Очистить результаты сеанса» удаляет текущий результат приложения; загруженный файл может оставаться в браузерном виджете до удаления пользователем/закрытия сеанса. Политику системных временных файлов, память браузера и доступ к компьютеру необходимо учитывать отдельно.

## Проверки

```powershell
python -m unittest discover -s tests -p test_ui_helpers.py -v
```

Тесты проверяют сохранность первого оригинала, повторные исправления и отмену, увеличение версии без автоматического одобрения, раздельное подтверждение содержания/экспорта, ошибки дат и IANA, обязательность объяснения, запрет подмены исходных полей и маркировку настоящего синтетического DOCX. Они не доказывают работу браузера, моделей или качество языков; эти проверки координатор выполняет отдельно.

В установленном окружении Streamlit дополнительно выполняются AppTest-сценарии настоящих виджетов: согласие, загрузка fixture, DOCX, ручная правка и сброс подтверждения, повторный просмотр, смена режима/примера, тишина. Проверка маршрута встроенного WAV использует подменённый аудиомодуль и доказывает только передачу вызова и отсутствие подстановки эталонного анализа, не качество модели.

Время аудио/анализа выводится только после фактического вызова на текущей машине. Оно не сравнивается с заранее придуманными эталонами. Режим синтетических данных не показывает фиктивное время обработки модели. Для ошибок используются фиксированные сообщения без записи, транскрипта и приватного пути.

## Сохранность предыдущего результата

При смене входа, метаданных или транскрипта прежний снимок вместе с анализом и user_edits сохраняется в истории сеанса. Доступны просмотр и скачивание JSON; удаление истории требует отдельного подтверждения. История находится в RAM сессии и не восстанавливается после перезапуска — нужные версии следует скачать локально. Дополнительные проверки увеличили набор helper/UI до 28 тестов.
