# Локальное аудио и разделение голосов

Модуль `audio.pipeline.transcribe` использует настоящие локальные нейросетевые модели: многоязычный Whisper через faster-whisper на CPU/int8 и WeSpeaker через sherpa-onnx. Заглушки используются только в unit-тестах и не включаются в рабочий путь.

## Вход и запуск

```python
from audio import transcribe

result = transcribe(
    r"C:\local-data\synthetic-meeting.wav",
    {"started_at": "2026-09-23T10:00:00+05:00", "timezone": "Asia/Qyzylorda"},
    [],
    asr_model_path=r"C:\local-models\faster-whisper-small",
    speaker_model_path=r"C:\local-models\wespeaker_en_voxceleb_resnet34_LM.onnx",
    num_speakers=2,
)
```

Пути выше — примеры; замените их реальными локальными путями. Можно задать переменные `QONIMAI_ASR_MODEL` и `QONIMAI_SPEAKER_MODEL` вместо аргументов. Число говорящих задаётся человеком, допустимо 1–8. Это число кластеров, а не число автоматически установленных личностей. Имена каждому `spkN` подтверждает пользователь в интерфейсе.

Результат: `{status, data, error}`; `ok` содержит Transcript v1, `no_speech` — корректный пустой транскрипт, `error` — фиксированный код и понятное сообщение без транскрипта и путей. Все `speakers` первоначально `confirmed=false`, `participant_id=null`, `display_name=null`.

Лимиты: 50 МиБ и 300 секунд. PyAV декодирует поток в mono float32 16 кГц и останавливается при превышении длительности. Отдельный системный FFmpeg не нужен.

Декодер разрешает FFmpeg только протоколы `file,pipe`: локальный файл-плейлист не может инициировать HTTP/HTTPS-загрузку вложенной записи. URL, UNC, сетевые диски Windows, junction/symlink и имена устройств не принимаются как входные пути.

## Модели и первоначальная подготовка

Основной ASR — `Systran/faster-whisper-small` (многоязычный), запасной — `Systran/faster-whisper-base` (тоже многоязычный). `.en` модели не подходят. Small занимает ориентировочно 0,5 ГБ на диске, base около 0,15 ГБ; точный размер фиксирует процедура скачивания. CPU/int8 применён ради 16 ГБ RAM и отсутствия NVIDIA. Опубликованный разработчиком ориентир small/int8 — около 1,5 ГБ RAM на другом процессоре; это не измерение нашего компьютера и не обещание скорости. [Документация faster-whisper](https://github.com/SYSTRAN/faster-whisper), [Whisper MIT license](https://github.com/openai/whisper/blob/main/LICENSE).

Основной extractor голосов — [`wespeaker_en_voxceleb_resnet34_LM.onnx`](https://github.com/k2-fsa/sherpa-onnx/releases/download/speaker-recongition-models/wespeaker_en_voxceleb_resnet34_LM.onnx), **26 530 550 байт** по официальному GitHub release API. [Исходная карточка весов](https://huggingface.co/Wespeaker/wespeaker-voxceleb-resnet34-LM) указывает CC-BY-4.0; укажите авторство WeSpeaker в описании моделей. Код sherpa-onnx/WeSpeaker имеет Apache-2.0, что не заменяет лицензию весов. [Официальный API](https://k2-fsa.github.io/sherpa/onnx/speaker-identification/index.html), [пример Python](https://github.com/k2-fsa/sherpa-onnx/blob/master/python-api-examples/speaker-identification.py).

Первоначально координатор скачивает библиотеки и веса из официальных источников, сохраняет их локально и проверяет контрольные суммы. Аудио при этом никуда не отправляется. Для ASR должны присутствовать как минимум `model.bin`, `config.json`, `tokenizer.json` и файлы словаря из того же официального снимка. VAD Silero поставляется внутри faster-whisper. Программа принимает только существующие локальные пути; `local_files_only=True` и обязательный tokenizer.json исключают загрузку tokenizer через hub во время обработки. Автоматического скачивания моделей нет.

## Как получаются голоса

1. Silero VAD определяет присутствие речи. Отсутствие текста после найденной речи возвращается как `EMPTY_MODEL_OUTPUT`, а не тишина.
2. Whisper выполняет `task=transcribe`, `multilingual=True`, с таймкодами слов. Исходный язык не переводится намеренно.
3. Слова делятся на речевые фрагменты около 2,5 секунды и по паузам; текст не придумывается и временные метки не распределяются пропорционально длине текста.
4. Из аудио каждого фрагмента WeSpeaker извлекает embedding. Косинусная кластеризация average-linkage объединяет их в заданное число голосов.
5. Соседние фрагменты одного кластера объединяются в реплику. Номера кластеров стабильны по первому появлению.

Это базовая диаризация по акустическим признакам. Она не разделяет одновременно наложенные голоса. Короткие реплики, шум, смена микрофона и неверное число говорящих снижают точность. При недостатке пригодной речи возвращается ошибка; заглушка с одним голосом не подставляется. Если ASR не вернул слова, весь его сегмент получает один голос, поэтому смену внутри такого сегмента нужно исправить вручную. WeSpeaker обучен на VoxCeleb; качество русского, казахского и смешанного разговора отдельно проверяется на контролируемых записях. Поддержка языков моделью не является подтверждением качества на наших данных.

## Проверка

Из корня репозитория, в подготовленной среде:

```powershell
python -B -m unittest discover -s tests -p test_audio_pipeline.py -v
```

Unit-тесты проверяют контракт, разграничение тишины/сбоя ASR, ошибки моделей, ограничения размера/длительности, отсутствие назначения имён и кластеризацию. Модели в unit-тестах подменяются; эти тесты не доказывают качество распознавания. Если PyAV установлен, выполняется реальная проверка декодирования вымышленного стереосигнала и ограничения длительности. Реальный прогон моделей, время, оборудование, языковые результаты и проверку без интернета координатор фиксирует отдельно в отчёте проверки проекта.

## Реальный контрольный запуск 23 сентября 2026

Координатор выполнил холодный запуск реальных локальных моделей на `fixtures/audio/synthetic_ru_two_speakers.wav`: 29,018 секунды вымышленного русского диалога, офлайн синтезированного Windows System.Speech голосами Microsoft Irina и Microsoft Pavel. Люди не записывались. Эталон фраз и ролей находится в `fixtures/audio/synthetic_ru_two_speakers.json`; первичный результат запуска — в локальном `runtime/asr-smoke-ru.json` (runtime не публикуется автоматически).

Среда: Windows 11, Intel Core i7-13620H, около 15,7 ГБ RAM, CPU без NVIDIA. CPython 3.12.14; faster-whisper 1.2.1, CTranslate2 4.8.2, sherpa-onnx 1.13.8, PyAV 18.1.0, NumPy 2.3.5. ASR — многоязычный small/int8, 4 потока; WeSpeaker ResNet34 LM — CPU, 2 потока. Полное время холодного вызова **101,111 секунды**, примерно 3,48 длительности записи. Это измерение данной записи и машины, а не гарантированная скорость.

Получен `status=ok`, шесть реплик. После сопоставления известных синтетических голосов последовательность `spk1, spk2, spk2, spk1, spk1, spk2` совпала с эталонными ролями в **6 из 6 реплик**. Это проверка ролей по репликам, не DER и не точность на реальных совещаниях. Имена в выходе автоматически не присвоены, все связи остаются неподтверждёнными.

Проверка содержания выявила конкретные исправления перед анализом:

- В репликах s1 и s5 имя «Данияр» распознано как «Даньяр» — нужно исправить вручную, иначе исполнитель может остаться неизвестным.
- В s5 и s6 множественное «предложения» распознано как единственное «предложение».
- Полная произнесённая дата передана цифрами `30 сентября 2026 года` с сохранением смысла.
- «Завтра» сохранено, у третьего поручения срок не добавлен.

WER/CER не заявлены: для их сопоставимости сначала нужна согласованная нормализация числительных и пунктуации. Произвольная замена числительных после запуска исказила бы метрику. Текущая проверка фиксирует перечисленные фактические расхождения.

После усиления локального декодера выполнены **29 unit-тестов, все 29 прошли, пропусков нет** (0,543 секунды), включая реальное преобразование PyAV стерео 8 кГц → mono 16 кГц и остановку по лимиту длительности. Повторный тяжёлый ASR для этой защиты не запускался: параметры моделей и кластеризация не изменялись. Казахская речь, смешанная речь, живые голоса, шум и перебивания этим запуском **не проверены**; полноценная приёмка этих требований остаётся открытой.
