# Локальный анализ через llama.cpp

Реализован `analysis.local_model.analyze(transcript, *, base_url="http://127.0.0.1:8081", model="local", timeout=180)`. Вход и выход — контракт v1. Модуль использует только стандартную библиотеку Python и существующий `parse_model_output`; модель не загружает.

Сначала отдельно получите выбранные веса и исполняемый файл llama-server из официальных источников. Для обработки сервер должен запускаться с локальным файлом весов, привязкой `--host 127.0.0.1 --port 8081 --alias local` и контекстом около 8192 токенов. Версию бинарного файла, модель, лицензию и точную команду запуска фиксирует координатор после smoke-теста. Не включайте подробный вывод запросов и реплик в журналы сервера. Этот модуль ничего не записывает и не печатает.

Адаптер обращается к `/v1/chat/completions`, отправляет русский системный промпт, метаданные даты/зоны и исходный транскрипт. `temperature=0`, `stream=false`, максимум 1600 токенов ответа. Ответ ограничен схемой `response_format={type: "json_object", schema: ...}` согласно [официальной документации llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md). Схема ограничивает идентификаторы реальными участниками/голосами/сегментами, номер версии — текущим значением, `user_edits` — пустым массивом. Полный ответ затем проходит независимую проверку `parse_model_output`. Промпт и грамматика не доказывают фактическую истинность вывода.

Промпт содержит четыре небольших вымышленных учебных примера, которые не совпадают с контрольными fixtures: несколько разных поручений, обсуждение без поручений, поручение без срока и казахское поручение с буквальным сохранением срока. Они используются только как контекст модели; при ошибке нет подстановки примера вместо ответа. В грамматике поручения генерируются до саммари. Автор ограничен голосами, которые реально имеют реплики в текущем снимке. Календарная подсказка для «завтра» добавляется только если это слово присутствует в репликах; сама подсказка не считается произнесённым сроком и не создаёт поручение.

Используется полная оболочка AnalysisResult: промежуточный формат и последующее переписывание версии не применяются. Неправильный номер версии, выдуманные ссылки и ручные правки модели отклоняются. Пустые корректные segments дают no_speech без обращения к модели; это не заменяет проверку настоящей тишины аудиомодулем. Для непустого разговора без поручений требуются содержательное саммари и tasks=[].

## Ограничения MVP

- Только буквальные адреса `http://127.0.0.1[:port]` и `http://[::1][:port]`. Даже `localhost`, внешний сервер, proxy, перенаправления и дополнительные пути запрещены. Переменные HTTP_PROXY/ALL_PROXY не используются. Закрытый удалённый сервер этой версией адаптера не поддерживается.
- До 80 сегментов и 8000 символов сериализованного JSON на один вызов. Более длинный вход отклоняется полностью как MODEL_CONTEXT_LIMIT, без скрытого обрезания.
- Максимум 1600 токенов ответа и 256000 байт HTTP-оболочки. `finish_reason=length` отклоняется: частичный протокол не показывается как успех. Длинные совещания и множество поручений требуют отдельного разбиения и объединения результатов, пока это не реализовано.
- Схема ограничивает саммари шестью пунктами, поручения и решения — двенадцатью каждого вида. Такой лимит рассчитан на короткое демо, а не промышленную обработку.
- `timeout` — таймаут сетевой операции urllib, не гарантированный общий срок фоновой задачи; сервер после прекращения ожидания может ещё выполнять запрос. Автоматических повторов нет.
- Отсутствие модели, ошибки HTTP, таймауты и непригодный JSON возвращают явную фиксированную ошибку. Текст ошибки сервера и исходный ответ не копируются пользователю. Регулярные выражения не используются для имитации анализа.
- На этом этапе юнит-тесты подтверждают только транспорт, ограничения и проверку ответа. Качество русского, казахского и смешанной речи, реальные скорость/память и работа конкретного GGUF должны проверяться отдельно.

## Проверка

Из корня репозитория выбранным Python с зависимостями проекта:

```text
python -m unittest discover -s tests -p test_local_model.py -v
python -m unittest discover -s tests -p test_model_output.py
python -m unittest discover -s tests -p test_contracts.py
```

Тесты local_model поднимают временный синтетический HTTP-сервер только на 127.0.0.1. Они не загружают и не вызывают LLM, не используют реальные совещания и не обращаются во внешнюю сеть. Подмена HTTP-ответа существует только внутри тестов.

Фактическая проверка 2026-09-23 на Windows и bundled Python 3.12.14 с IANA: 29 тестов local_model прошли; регрессия model_output — 57 прошли, 1 пропущен; contracts — 91 прошёл, 1 пропущен. Оба пропуска относятся к проверке реально отсутствующей базы IANA, которая в этой среде доступна. Тесты не являются проверкой качества LLM.

Перед демонстрацией координатор должен запустить настоящий локальный сервер, выполнить вымышленный диалог через `analyze`, проверить результат по смыслу, замерить время и повторить обработку без внешнего интернета с уже загруженными весами. Получение весов и автономная обработка — разные этапы.

## Фактические модельные проверки 2026-09-23

Использованы только заранее вымышленные случаи и синтетическая запись. Qwen2.5-1.5B не прошёл семантическую проверку: модель путала людей, придумывала сроки и смысл казахских реплик. Его успешный JSON нельзя считать правильным протоколом.

Координатор переключил сервер на Qwen3-4B-Q4_K_M, llama.cpp b11125, CPU, 6 потоков, контекст 8192, без reasoning. На первой версии промпта Qwen3 дал пригодные RU_EXPLICIT (53,26 с), NO_DUE (19,33 с), NO_TASKS (17,67 с), MIXED (22,58 с). В TOMORROW_YEAR срок вычислен правильно, но саммари выдумало согласие; KK_EXPLICIT отклонён за изменённую цитату срока. На первом прогоне записи извлечены только два из трёх поручений. Это основания для изменения промпта, а не пройденная приёмка.

После добавления учебного примера нескольких поручений последний проверенный промпт дал:

| Случай | Время | Фактический результат |
|---|---:|---|
| TOMORROW_YEAR | 76,80 с | Отклонён: модель добавила лишнее поручение с противоречивыми уточнениями |
| KK_EXPLICIT | 48,77 с | Отклонён: неверная нормализация срока и источник автора |
| Синтетическая запись, 6 реплик, 3 поручения после проверки ASR | 68,86 с | Все 3 поручения, исполнители, сроки и саммари проверены и соответствуют заданному сценарию |

Успешный последний результат: Данияр — таблица расходов до 2026-09-30; Ирина — проверка списка поставщиков до 2026-09-24 («завтра» от даты совещания 2026-09-23); Данияр — предложения коллег без срока, с missing_due. Отдельно сохранены исходный ASR, исправленный снимок revision=2 и описание ручной проверки. Исправления до анализа: подтверждение spk1→Ирина, spk2→Данияр; «Даньяр»→«Данияр» и число слова «предложения» по известному синтетическому сценарию. Текст ответа модели не переписывался.

Локальные свидетельства: `runtime/llm-qwen3-4b-semantic-smoke.json`, `runtime/llm-qwen3-4b-recheck.json`, `runtime/endtoend-asr-original-transcript.json`, `runtime/endtoend-reviewed-transcript.json`, `runtime/endtoend-review-provenance.json`, `runtime/endtoend-analysis-recheck.json`. Это результаты выполненных запусков, а не ответы, подставляемые анализатором. Runtime не предназначен для публикации реальных совещаний в Git.

**Вывод приёмки:** один сквозной синтетический сценарий работает; универсальная семантическая надёжность не достигнута. Казахский текст и устойчивость на других формулировках ещё не приняты. Результат требует просмотра и исправления человеком. Предыдущие успешные случаи с другим промптом не считаются повторно проверенными на последнем промпте. Полный автономный запуск и проверку оборудования оформляет координатор отдельно.
