## Решения по вопросам реализации

1. Для среды проверки фиксируем tzdata==2026.3 в requirements-validation.txt. Подтверждённый Python 3.12.14 — среда проверки валидатора; версии Python и библиотек всей цепочки ещё не выбраны. Пакет даёт реальную базу IANA; фиксированный +05:00 и подстановка UTC не допускаются.
2. Ограниченный детерминированный разбор дат принимаем с описанными ограничениями. Не обещаем поддержку всех естественных формулировок. Истинность произвольного пересказа, назначение исполнителя и отмена требуют анализа и просмотра человеком.
3. Непустой user_edits в сыром ответе модели должен отклонять будущий адаптер. validate_analysis сознательно допускает итоговое состояние после правок UI. Эти границы нельзя смешивать.
4. Уточнения и флаг являются производными: самостоятельное редактирование только текста причины не добавляем в UI первого MVP. Меняются описание, ответственный, дата; причины пересчитываются.
5. error.code остаётся открытой непустой строкой. Повтор ссылок на один сегмент не блокирует снимок: в текущей спецификации нет такого запрета. Извлечение по возможности формирует ссылки без повторов; закрытый enum или новая обязательная уникальность требуют отдельного изменения контракта.
6. Один снимок не доказывает историю ручных правок. UI отвечает за исходный original, revision, сброс reviewed_revision и запрет скрытой перезаписи. Проверка структуры не устанавливает факт пользовательского согласия.
